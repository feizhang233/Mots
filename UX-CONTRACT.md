## Dictionary lookup and thematic study

Dictionary lookup searches the current dictionary's terms, displayed meanings and examples. It lists definitions/examples openly, in language-aware alphabetical order, with bounded pagination. It includes mastered entries and ignores study familiarity-hide filters, so a definition cannot disappear solely because it was learned. Chinese meaning script and honest missing-meaning messages remain consistent with study.

Thematic study retains two-level chapter/subchapter navigation for vocabulary and ordinary grammar. Thematic grammar uses first-level navigation and moves second-level titles onto expandable list cards. Only categories containing words in the current dictionary appear. Card/list, source-order/random order and reshuffle are study controls. Cards reveal meaning/example together and hide answers when moving to another word. Web list rows use two compact logical bands, about 85px for a single-line desktop entry and growing for long content; the only pronunciation button is to the left of the term.

Switching thematic study from card to list opens the current card's containing page and remembers that exact word. Returning to cards restores the word even when it is already rated, retaining the filtered/shuffled deck. Browsing list pages or changing page size does not overwrite the card position. If the word is removed, use a valid nearby word; a changed dictionary, study scope or order starts a new position. This navigation anchor is transient and does not change progress or backup formats. Native card/list navigation follows the same exact-word return rule, with the prior shuffled sequence retained.

On an initial list-to-card entry without a prior card position, start at the first visible, not-studied word at or after the current list page's start, wrapping once if necessary. If none is unstudied, retain the page's first word; empty results retain their empty state. A selected card starts with its answer hidden, and the list page follows the chosen word. Clicking the already active card control does not restart or jump.

Web cards include a labelled native range in the right sidebar directly below the familiarity statistics, with a visible current/total count such as 42 / 142. The former three shortcut-hint rows are removed. At narrow widths (including the single-column segmented-screen layout), hide only the statistics and retain this one range below the card navigation. Keyboard shortcuts remain functional. It spans the current filtered deck (or captured review queue) in its current order. Dragging, track clicks and native keyboard input select a word, hide its answer, clear end-of-group feedback and stop pronunciation without rating it or shuffling the deck. The slider and its ancestors remain connected while dragging so focus and continuous input survive card updates. Empty results have no slider; a single-word deck shows a disabled 1 / 1 control. Native iOS cards do not add this Web-only slider.

Familiarity remains 0 not studied, 1 unfamiliar, 2 partial recall, 3 mastered. Lists use green/orange/red dot buttons with ring/checkmark and `aria-pressed`; pressing the selected mark clears it. Card marks remain labelled. Hidden levels are any combination of 0–3, persisted per dictionary. A captured review only removes deleted members and related rating bookkeeping; restoration does not add words to the current round. Stale rating callbacks cannot rate a deleted word. Stop audio for a locally or remotely deleted playing word. Preserve unknown deletion records, restored false records and edits made while sync is in flight. Storage failures remain visible and prevent reporting full synchronization.

## Random review

Each round captures at most 20 unique, non-mastered entries from the current dictionary. Shuffle unfamiliar and partial-recall entries first, then fill any remaining slots from shuffled not-studied entries. Do not include mastered words. The round is independent of the current search, chapter, hidden-level setting, page and normal random-order deck.

Keep the captured round stable while ratings change; marking a card mastered must not unexpectedly re-filter or duplicate the remaining queue. Save familiarity to the active dictionary's progress store, then advance to the next card. Marking the last card, or manually moving forward from it, opens completion. Report the actual number rated versus round size, including rounds with skipped cards, and offer another round or dictionary lookup. An all-mastered or empty dictionary has an honest no-review state with a lookup route. A direct review URL starts a fresh round rather than rendering a normal study deck. This feature does not claim spaced repetition, due dates or a learning schedule.

## Persistence and backups

Built-in French progress keeps `mots.progress.v1`; German/Japanese keep `mots.progress.de.v1` and `mots.progress.ja.v1`. Custom dictionary progress uses `mots.progress.dictionary.<dictionary-id>.v1`. The dictionary library uses `mots.dictionaries.v1`; settings use `mots.settings.v2`, retaining the older language and display preferences for compatibility. Existing legacy extensions use `mots.banks.v1`.

Version 3 backups include imported dictionaries, all dictionary progress, settings and extensions. Built-in source data/audio remain packaged rather than duplicated in the backup. Version 1 French and version 2 three-language backups remain importable. Restoration accepts JSON up to 50 MB. Validate complete candidate dictionaries, category references and progress before merging. Known matching IDs take incoming values; unrelated existing dictionaries/progress remain. Invalid data must not partially mutate runtime content or persisted stores. A new-dictionary import always creates a fresh identity, even when the source JSON contains an existing dictionary ID.

Unpaired storage is browser-local. Optional private pairing synchronizes familiarity by exact dictionary/word ID over HTTPS without accounts; settings and custom dictionary definitions remain local. Pairing secrets stay out of URLs, logs, exports and backups. Local revision metadata persists atomically before sending, including level-zero tombstones; response merges use current local revisions so in-flight edits survive. Legacy seeds have clock zero, while subsequent actions advance a persisted Lamport counter. Disconnect invalidates pending responses without deleting progress. Foreground/online triggers and visible polling retry offline changes with bounded backoff. Storage errors retain in-memory work, show persistent unsaved status and recommend backup. Other-tab updates must select a valid existing dictionary and refresh its content/progress consistently. Clearing browser data clears imported dictionaries, preferences and progress.
