# Liquid Glass web migration — 2026-10-23

The active interface now uses a cool porcelain/green palette, platform system typography, translucent navigation and modal chrome, opaque reading surfaces, native Select controls and an iOS-style switch. The Material Web bundle, authored custom elements, build script and vendor inputs were removed. `src/components/select.js` is copied directly to `dist/select.js` by the ordinary dependency-free build.

`make test` passed: source/build consistency, four content/adapter syntax checks, all five application regression suites, and all eight deployment regression checks. The replacement Select suite covers synchronous first selection and dictionary updates, identity preservation, safe text labels, unchanged option lists, disabled/empty fallbacks, seven native selects and visible settings-label associations. Earlier custom-element race assertions are intentionally retired because that lifecycle no longer exists.

The strict premium audit was run and saved to `qa/glass-static-audit.json`. It reports 26 `affordance.actionless-button` findings and zero ownership/unresolved findings. These are the previously documented heuristic limitation: the scanner detects inline action attributes but does not resolve `addEventListener` or event delegation. The literal controls are bound in `src/js/app.js` (navigation 804–841, settings/home 862–909, search 1005–1033, view/order 1037–1059, templates and export 1223–1349); dynamic category/rating/card/library controls use delegates at 804, 869 and 1063. The runtime regression suites exercise those workflows. The audit is **not** recorded as passing.

The initial offline attempts had no cached packages. The main task subsequently ran the official `designmd` linter and Prettier using a temporary npm cache (no project dependency added). Design lint passed with zero errors and 16 orphan-token warnings; these tokens are consumed by CSS, while frontmatter component maps remain empty. Prettier corrected three files and the final `--check src tests` passed. Logs are in `qa/ios/design-lint.log` and `qa/ios/format-check.log`. Color, font and shape values were traced between `DESIGN.md` and the canonical variables in `src/styles/styles.css`; `select.css` and `workspace.css` consume that source.

Searches of active source/build tooling found no Material imports, custom tags or `--md-` tokens. No browser `alert`, `confirm`, `prompt` calls or non-semantic `onClick` controls were introduced. Existing local IME-aware search, storage/invalid-import recovery, review completion, dynamic document title and modal focus behavior remain intact.

Dark theme, reduced-transparency/reduced-motion fallbacks, forced colors, mobile safe areas, dynamic modal heights, 44px mobile chrome targets and a segment-aware Duo layout are implemented. Browser screenshots/workflow results are tracked separately by the main task. Hardware hinge behavior, real iPhone touch/VoiceOver and native app compilation must not be inferred from these web checks. There was no deployment or publication.
